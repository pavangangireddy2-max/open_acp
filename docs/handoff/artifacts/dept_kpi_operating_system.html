1. Ownership rules (read first)

RuleMeaning
KPI owner = laneExactly one lane is answerable for each number. A second lane may be "informed," never co-owner.
Deliverable owner = per itemRoadmap items are executed by PMs, engineers, or SMEs (the sheet's SME-Led / Dev-Led / Product-Led tags). One KPI is routinely moved by deliverables from different role types — no conflict with the rule above.
Lens modelCapabilities are shared objects; metrics are lane-owned. Platform lens (LP): adopted, engaging, consistent? · Domain lens (LD): does it teach — valid evaluation, real upskilling? · Infra lens (DP): does it run? · Product lens (PLE): delivered right per product?
⚓ Domain anchorA capability existing for one domain (SQL env, DSA visualizer, n8n, NxtTalk, ROS 2) is anchored: the domain owns its outcome case; Learning Platform keeps only design-consistency and instrumentation. One registry, no per-domain lists.
Capability vs journey (the LP/PLE line)Learning Platform owns capability numbers, measured platform-wide — adoption, engagement, feature reliability. Product Learning Experience owns journey numbers, measured per product — right capability at the right step, configured right, on schedule. A number about a feature → LP; a number about a product's step → PLE.
Cascade ruleA KPI may feed multiple NIAT targets (Program Delivery Gap → university CSAT + academics CSAT); ownership stays single.
Roadmap hygieneEvery roadmap row carries: lane tag + impacted KPI (from the named list) + execution owner. Free-text metric categories retire.

5. Operating rules

RuleMeaning
Adoption gateNo capability ships without a registry row, an adoption target, and instrumentation. The bookmarks lesson: built first, 60% dead clicks discovered later.
Instrumentation firstCapability Adoption Rate reports only on instrumented rows — the mostly-"?" column is the first sprint of Learning Platform scorecard work.
Never orphanedEvery roadmap row that ships a capability adds/updates a registry row; every KPI maps to a lane; every lane KPI names its NIAT-target linkage or is explicitly internal.
Close the loop, visiblyStudent-facing issue lifecycles carry four communication touchpoints: acknowledge (hours) · progress update (weekly once past TAT) · fix notification (resolved = fix live + students told) · re-open rate as the diagnostic that validates fixes. One standard, instantiated per audience — students, universities (University Communication TAT), instructors.
4-checkbox closeAn issue/theme is closed only when: instance fixed · producing artifact changed · tripwire added · broadcast sent. Powers both Recurrence KPIs and Theme Closure.
Complexity multipliers1.0x (English/Aptitude/Maths) to 2.5x (System Design/DS&Algo/DS-ML) normalize every velocity and cost target across domains.
Commissioning metrics retireMeters (Cost-Attribution Coverage) leave the scorecard once they hold 100% for 2 months — instruments aren't KPIs forever.
