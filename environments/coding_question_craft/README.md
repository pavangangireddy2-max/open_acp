# coding-question-craft

Train a model to **author** programming problems. The model is given a spec
(topic + difficulty) and must produce a complete problem — statement, a
reference program, and test cases. Scoring is **deterministic**: we execute the
model's own reference program against its own tests in a guarded subprocess, so
a question only scores well if it is actually solvable and internally
self-consistent. No judge is needed for the core signal.

### Overview
- **Environment ID**: `coding_question_craft`
- **Framework**: verifiers **v1** (`import verifiers.v1 as vf`)
- **Tags**: code-generation, problem-authoring, train, eval

### Contract
The model responds with a single fenced ```json block:

```json
{
  "title": "...",
  "difficulty": "EASY|MEDIUM|HARD",
  "topics": ["..."],
  "statement": "markdown with Input/Output sections",
  "reference_solution": "a full Python program that reads stdin, prints stdout",
  "tests": [{"input": "<stdin>", "expected": "<stdout>"}]
}
```

This stdin/stdout program contract matches the verified `programming_algorithms`
corpus, so generated questions are directly usable on the same platform and the
corpus doubles as a gold calibration set.

### Datasets
- **Specs** are generated by `build_specs(n, seed)` — a deterministic sampler
  that draws topics from the real corpus frequency distribution
  (`data/taxonomy.json`, 21 topics) and cycles difficulty for training coverage.
- **Gold set** (`data/gold_coding.json`) — 340 human-authored, verified CODING
  questions, normalized to the contract above. Used for reward regression, not
  for rollouts. Regenerate with `scripts/extract_corpus.py`.
- **Exemplars** (`data/exemplars.json`) — verified questions (self-consistency
  checked at extraction) embedded as few-shot in the authoring prompt.

### Rubric
Format validity and test-count act as **gates** (fail → substantive rewards
zero). Reward mass sits on the discriminative axes (max total 7.0):

| reward | weight | meaning |
| --- | --- | --- |
| `format_valid` | 0.5 | parses to the schema (small residual signal) |
| `tests_pass` | 3.0 | fraction of the reference's own tests that pass |
| `solvable` | 2.0 | reference passes **every** test, no error |
| `non_trivial` | 1.5 | no trivial baseline (const/echo/empty) passes; ≥2 distinct expected |

Metrics (observability only): `num_tests`, `difficulty_match`, `trivial_solved`,
`distinct_expected`, `edge_inputs`. Edge coverage is a metric, not a reward —
the gold-set regression showed verified authors don't follow any cheap edge
heuristic.

### Quickstart
```bash
# install (editable) from the repo root
uv pip install -e environments/coding_question_craft

# regenerate bundled data assets from the corpus
python environments/coding_question_craft/scripts/extract_corpus.py

# reward calibration against the 340 verified questions
python environments/coding_question_craft/scripts/gold_regression.py

# eyeball the generated specs
python environments/coding_question_craft/scripts/gen_dataset.py 12 0
```

A local eval baseline (OpenRouter, in-process, local subprocess runtime) is
driven by `scripts/run_cqc_baseline.py` at the repo root; it needs
`OPENROUTER_API_KEY` in the environment.
